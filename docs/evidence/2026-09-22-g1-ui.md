# Day 06 — protected voice investigation

Implemented and verified locally on **23 September 2026**. The filename follows the assignment date.
Branch: `feature/voice-kpi-incident-investigation` (shared with Day 05).

## Verified result

The real `telecom.test:8080` proxy, branded Keycloak login, Spring session,
PostgreSQL, Kafka, generator, processor and Angular production build were used.
The browser test creates a temporary local Keycloak analyst, signs in normally,
and removes that account and its analyst mapping afterwards. Passwords and tokens
are not saved in screenshots, traces, storage state or the evidence document.

The generator published 16 measured synthetic observations for eight UTC minutes,
`2026-09-23T08:36:00Z` through `2026-09-23T08:44:00Z`. These are demo measurements,
not operator telemetry. KPIs and detections were calculated by the running
processor, persisted by the incident service and retrieved over protected APIs.
No canned detection was injected and no browser response was mocked.

Resulting incident: `5d491dcd-86ec-4ae1-b71a-a3ec8eda0041`.
One episode, eight KPI windows, six evidence updates:
OPEN, UPDATE, UNKNOWN, UPDATE, UPDATE, RECOVERY.
The missing measurement remains a gap, technical state is RECOVERED and workflow
state remains OPEN. Every detection's KPI array matched its backend history
window, and the detail page showed the same CSSR and denominator values.

An exact replay was published. After Kafka acknowledged consuming the replay,
the observation count remained 16, the incident was unchanged and all six
evidence records and all eight KPI windows were unchanged. Logout restored anonymous JSON 401 responses.
Local/session browser storage stayed empty.

## Reproduce

Follow [the Day 06 instructions](../tasks/day-06-protected-voice-investigation/README.md).
With the complete local stack and incident service running:

```bash
cd apps/dashboard
G1_WINDOW_START=2026-09-23T08:36:00Z npm run test:g1
```

Use a fresh non-overlapping completed eight-minute range for a new episode.
Reuse exactly the same start and seed for replay. Historical windows older than
the processor's per-scope evaluated watermark remain available as KPI history
but do not rewrite existing episodes. This is a local CLI-driven demonstration;
the public scenario scheduling API is not implemented by this task.
