## Required result

The G1 gate requires a second setup to perform a real browser login, schedule
the `VOLTE_IMS_OVERLOAD` profile through the public command API, observe the
generated voice profile through Kafka and the processor, display one persistent
incident in the dashboard, then restart/re-login and retry the same command
without creating a duplicate incident.

The executable flow is [first-slice.spec.ts](../../tests/e2e/specs/first-slice.spec.ts).
It uses the contract-defined routes, CSRF header, stable `requestId`/`runId`,
and the `VOLTE-MD-CENTRAL` scope. It fails explicitly when credentials or an
application surface is unavailable; it does not convert an unavailable
dependency into a passing test.

## Blocking evidence

The current checkout contains no runnable backend, Keycloak, NGINX, dashboard,
or scenario scheduler. The Compose file currently starts only PostgreSQL,
Kafka, `kafka-init`, `event-generator`, and `processor`; the generator is
explicitly a deterministic preview boundary and does not publish observations
or expose a public simulator command. Therefore there are currently no real
login credentials, `runId`, incident ID, dashboard URL, or measured end-to-end
wait time to record.

The OpenAPI contract itself marks these application endpoints as implementation
work. Claiming G1 complete from the healthy containers would violate the gate
acceptance criteria.
