## Field meanings and limits

The [live comparison](assets/backend-g4/contract-comparison.json) matches the two protected HTTP incident responses to persisted rows field by field. `technicalState=RECOVERED` describes detector health; `status=RESOLVED` is the analyst action. `version` is the workflow concurrency token; `latestSequence=5` points to the immutable `RECOVERY` detection. VoLTE `cssrPct` carries its 940/1000 fault numerator/denominator and nulls remain null for missing windows. SMS p95 delivery is milliseconds; queue depth is a count. The latest probable-cause text remains qualified (`LOW` confidence) rather than asserting a root cause. UTC timestamps are compared as instants, avoiding representation-only differences. The browser shows the same service title, severity, technical state and analyst workflow as the protected response.

This is local synthetic evidence for the configured footprint. DATA and roaming remain additive work. Device measurements and topology drill-down APIs remain unavailable. The 72-second load sample does not establish peak throughput or endurance. Teammate acknowledgments are not claimed; the user directed completion without waiting for external review.

## Reproduce

On a disposable local stack with the repository's existing environment configured:

```sh
./scripts/up --with-incident-service
./scripts/verify
./mvnw -q verify
.venv/bin/python scripts/check-contracts.py
npm --prefix apps/dashboard run check:fixtures
npm --prefix apps/dashboard run generate:api
E2E_RELEASE_LIVE=1 npm --prefix apps/dashboard run test:e2e -- --config playwright.demo.config.ts --grep 'release roles'
E2E_PERFORMANCE_LIVE=1 npm --prefix apps/dashboard run test:performance:live
```

The long browser audit creates temporary local role accounts and starts two eight-minute synthetic scenarios. If it has already recorded both real runs and stops later in the flow, save its `release-results.json` outside `test-results` first and set `RELEASE_RESUME_RESULTS` to that absolute path for a resumed run or the `matches live incident fields` test. A resumed run verifies the original run IDs and skips completed/resolved investigations; it does not substitute fixtures. The SQL used for the measured publication count is retained in [load-publication.json](assets/backend-g4/load-publication.json).
