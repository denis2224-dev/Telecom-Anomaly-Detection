## Day 13 — durable jobs and episode replay safety

`DetectionWorker` persists a UUID lease for the oldest unfinished feature window
per scope. Its claim commits before HTTP inference. A compare-and-set on the
unexpired token gates one transaction containing completion, evaluated-window
identity, episode state, and both output types. Stale results cannot overwrite
committed evidence when the ML service recovers. Existing callers continue through
`VoiceDeliveryService`; the durable service-neutral records use the existing table
names to avoid an unrelated migration.

KPI/detection output uses persisted head claims per `(topic,kafka_key)`. A claimed
or otherwise unpublished predecessor blocks later windows/sequences. Broker I/O
holds no database transaction; only the current token can mark acknowledgement.
V006 backfills completed jobs without changing saved features, episode state,
delivery IDs/payloads, or timestamps. Runtime may change delivery bookkeeping,
but cannot update payload, ID, topic, or key, and cannot create database objects.

| Boundary | Verification |
| --- | --- |
| Two detector claimants, both services | Exactly one owner of the head; one completion; next window ordered |
| Crash after claim / lease expiry | New token claims the same window; stale completion rejected |
| Episode/output write and deferred commit failure | All completion changes rolled back; expired retry creates one logical result |
| Concurrent output publishers | Sequence 2 withheld while sequence 1 waits for acknowledgement |
| Stale publication acknowledgement | Obsolete token cannot mark a replacement owner's claim |
| Acknowledged send, failed database mark | Existing `ReplayIT` resends identical committed output |
| ML restored after saved result | Saved episode and detection snapshot unchanged |
| Schema upgrade from V005 | Existing records unchanged; only pending work remains pending |

Delivery remains **at least once**, including the acknowledgement-before-mark
crash window. A database lease cannot revoke an already in-flight Kafka request.
