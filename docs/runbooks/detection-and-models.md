# Detection and model operations

Deterministic detection remains authoritative when optional ML is unavailable, malformed, non-finite, mismatched, rejected or timed out. Keep ground truth and future outcomes outside detector input. Cause attribution requires valid mapping, overlapping fresh qualified evidence and topology version; unsupported attribution stays undetermined.

Use the [scoped scenario procedure](trace-link-scenario-runtime.md), [producer procedure](trace-link-domain-producers.md), [ML shadow procedure](trace-link-ml-shadow.md) and [streaming operations](streaming.md). Supported positives and controls must retain stable retry/run/window/episode identities across stop, restart and replay. An advertised but unsupported scenario is unavailable, not an executable approximation. Stopped telemetry cannot prove recovery.

The complete Linux ML test run retained its strict Windows artifact byte-rebuild failure. Unchanged model source passed actual upstream Windows reproduction; this does not establish full branch CI. Do not regenerate pinned artifacts or weaken byte assertions to conceal a platform mismatch. Consult the [verification record](../evidence/assets/trace-link-completion/verification.json) and [scoped CI evidence](../evidence/assets/trace-link-completion/upstream-model-ci.json).

For the old missing-window lifecycle failure, obtain retained runtime logs/database evidence before assigning a cause. The [completion runbook](trace-link-completion.md#missing-window-investigation) preserves identifiers and the distinction between a controlled reproduction and a proven historical explanation.
