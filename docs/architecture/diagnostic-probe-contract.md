# Diagnostic Probe Foundation

This is an infrastructure boundary, not a telecom health classifier. Probe
results are evidence about the specific controlled reachability check and must
not be converted directly into `POWER_OFF`, `VoLTE failure` or another root
cause.

## Controlled contract

Each future probe result should contain:

| Field | Requirement |
| --- | --- |
| `probeId` | Unique identifier for one execution |
| `targetId` | Inventory identifier, never a user-supplied URL/IP/port |
| `targetType` | Controlled enum such as `HTTP_READINESS` or `TCP_REACHABILITY` |
| `protocol` | Protocol selected by the inventory entry |
| `observedAt` | UTC timestamp generated by the worker |
| `result` | `SUCCESS`, `TIMEOUT`, `REJECTED`, `TARGET_UNAVAILABLE`, `WORKER_UNAVAILABLE` or `ERROR` |
| `latencyMs` | Bounded elapsed time when the worker reached the target |
| `errorCategory` | Safe category only; no credentials, tokens or raw secret-bearing diagnostics |
| `workerStatus` | `HEALTHY`, `DEGRADED` or `STOPPED` |
| `freshness` | `CURRENT`, `STALE` or `UNKNOWN`, based on an explicit age limit |

The final wire schema must reuse an existing project contract if one is added
before implementation. This document intentionally does not add a network
adapter or dashboard endpoint.

## Safety boundary

- Targets come from a versioned allowlist owned by infrastructure.
- Untrusted callers cannot supply an arbitrary URL, hostname, IP address or port.
- Each execution has a fixed timeout, retry budget and concurrency limit.
- A stopped worker produces `WORKER_UNAVAILABLE`; it must not be reported as a
  target outage.
- A stale result is not current health evidence.
- A successful check proves only the selected protocol and target reachability.
- A failed check can represent target unavailability, route filtering or worker
  failure; it is not a root-cause conclusion.
- Results must be bounded in size and must not contain credentials, cookies,
  authorization headers or unrestricted response bodies.

## Verification matrix

| Case | Expected outcome | Evidence class |
| --- | --- | --- |
| Allowlisted local target | Success, target identity and UTC timestamp recorded | Controlled fixture |
| Unknown target ID | Rejected before any network request | Controlled fixture |
| Timeout | Bounded `TIMEOUT`; worker remains healthy | Controlled fixture |
| Age beyond freshness limit | `STALE`; not treated as current health | Controlled fixture |
| Worker stopped | `WORKER_UNAVAILABLE`; distinguishable from target failure | Controlled fixture |

The adapter and executable probes are intentionally deferred. This baseline establishes
the contract and safety constraints so later implementation cannot become an
SSRF-like arbitrary request mechanism.
